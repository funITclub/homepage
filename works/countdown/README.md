# カウントアップ＆ダウン

出来事・予定を登録すると、未来の予定は残り日数（カウントダウン）、過去の出来事は経過日数と
周年（カウントアップ）を出す Django アプリ。印を付けた予定の残り日数を、毎日メールで知らせられる。

hirahira_room の `countdown` アプリからの移植。あちらはユーザーごとの個人用だが、こちらは
**ログインなしで誰でも使える公開アプリ**（`/countdown/`）。公開サイトとは相互にリンクせず、
成果物紹介に登録した URL から辿る（fe と同じ）。

## 構成

| ファイル | 役割 |
|---|---|
| `models.py` | `Board`（ID ごとの置き場・通知先）と `CountEvent`（出来事・予定）。日数の数え方もここ |
| `views.py` | 紹介／ID で入る・作る／一覧・登録・編集・削除／通知先の設定／メールのリンク／定時送信の入口 |
| `forms.py` | ID の入力（入ると作るを分ける）・出来事の入力・通知先のアドレス |
| `notify.py` | メール通知（確認・解除のリンク、毎日の送信、送りすぎの歯止め） |
| `crypto.py` | 通知先のアドレスの暗号化 |
| `admin.py` | 荒らしの整理・使われなくなった ID の削除・通知先の消去 |
| `management/commands/send_countdown_mails.py` | 今日の分の通知を手で送る |

## URL

| URL | 内容 |
|---|---|
| `/countdown/` | 紹介 |
| `/countdown/enter/` | ID で入る・新しく作る |
| `/countdown/<ID>/` | その ID の一覧（登録・編集・削除は `create/`・`<番号>/update/`・`<番号>/delete/`） |
| `/countdown/<ID>/mail/` | その ID のメール通知の設定 |
| `/countdown/events/` | ID を使わない共有ボード（誰でも読み書きできる） |
| `/countdown/notify/confirm/<token>/` | 確認のメールのリンク（通知先の登録） |
| `/countdown/notify/stop/<token>/` | 解除のリンク |
| `/countdown/notify/run/` | 毎日 0 時の送信の入口（GitHub Actions から呼ぶ。POST だけ） |

`/countdown/<ID>/` が直下のほかの URL とぶつからないよう、`events`・`enter`・`notify` は ID にできない
（`forms.RESERVED_CODES`）。URL を足したら、ここにも足す。

サブアプリなので、ホームページの一覧から辿ったときだけ開く（`config/gate.py` の通行証）。
メールのリンクと定時送信の入口（`/countdown/notify/`）は、別の鍵（署名・合言葉）で守られているので
通行証なしで開ける（`GATE_EXEMPT`）。

## ID の考え方

- 会員登録がないので、アプリの中の ID（`Board`）ごとに出来事を分けて持つ。fe の `Learner` と同じ考え方。
- ID は本人が決める（英小文字・数字・`_`・`-` で 3〜30 文字。小文字にそろえる）。**合言葉はなく、
  ID を知っている人なら誰でも開けて書き換えられる。** 人に知られたくない予定は書かない前提。
- 打ち間違えた ID で新しく作らないよう、「入る」（既にある ID だけ）と「作る」（まだ無い ID だけ）を分ける。
- ほかの ID の出来事は、番号を言い当てても開けない（404。`BoardMixin` が置き場で絞る）。

## 日数の数え方

`CountEvent` のプロパティで計算し、DB には持たない（日付が変われば自動で進む）。

| | 条件 | 出すもの |
|---|---|---|
| カウントダウン | 日付が今日より後 | 残り日数（`残り`）と、週＋日 |
| 当日 | 日付が今日 | `当日` |
| カウントアップ | 日付が今日より前 | 経過日数（`経過`）と、何周年か（月日を過ぎたら 1 つ増える） |

「今日」は `timezone.localdate()`（日本時間）。

## メール通知

印（`CountEvent.notify`）を付けた、当日を含むこれからの予定の残り日数を、ID ごとに **1 日 1 通**にまとめて
送る。対象がない日は送らない。ID の一覧でだけ使える（共有ボードでは使わない）。

### 通知先の登録と解除

```
通知の設定（/countdown/<ID>/mail/）でアドレスを入れる
  → 確認のメール（リンクの期限 1 時間）
  → リンクを開く → 「受け取る」を押す → 通知先になる
解除：登録したアドレスに届くメールのリンク → 「通知を止める」を押す → アドレスを消す
```

| 決まり | 理由 |
|---|---|
| 通知先は ID ごとに 1 つ。確認のメールのリンクを開いて押したアドレスだけを持つ | 他人のアドレスを勝手に登録させない |
| 通知先がある間は、画面から変更も解除もできない。解除は登録したアドレスに届くリンクからだけ | ID を知っている人が、通知を止めたり自分のアドレスに差し替えたりできないように |
| 画面からは「解除用のメール」を登録したアドレスへ送れる | 通知が届かない日でも止められるように。解除のリンクは毎回の通知にも付ける |
| メールのリンクは、開いただけでは何もしない。ボタンを押したときに実行する | 受信側の検査がリンクを自動で開くことがあるため |
| 解除のリンクは、いまの通知先あてのものだけが効く | 通知先が変わったら、前のアドレスあてのリンクで止められないように |
| 確認のメールの送りすぎを数える（同じ IP 1 時間 10 件・同じアドレス 1 時間 3 件。`COUNTDOWN_CONFIRM_SEND_LIMITS`） | 第三者あてにメールを送り続けさせない。IP の遮断はしない |
| 本人がメールを受け取れなくなったら、admin の「カウント ID」で ID を選び、操作「選んだ ID の通知先を消す」 | 本人が自分で解除できないときの逃げ道 |

### 通知先のアドレスの持ち方

会としては個人情報をシステムに持たない方針で、ここは**その例外**。本人が通知を望んだときだけ持ち、
通知を送る以外には使わない。

- DB（`Board.notify_email_enc`）には**暗号化して**入れる（`crypto.py`。Fernet。鍵は `SECRET_KEY` に
  用途の salt を付けて作る）。DB の中身だけが漏れても読めない。`SECRET_KEY` まで取られたら防げない。
- 確認を待つ間のアドレスも、暗号化してキャッシュに置く（期限 1 時間）。確認のリンクには番号だけを入れ、
  アドレスは入れない。
- 画面には伏せて出す（`a***@example.com`）。admin には登録の有無だけを出す。ログにはアドレスを出さない。
- ID を消すと、アドレスも一緒に消える。
- `SECRET_KEY` を替えるときは、前の値を `SECRET_KEY_FALLBACKS` に残す（README の「環境変数（本番）」の注意）。

### 送信のきっかけ

App Service には常設のスケジューラがなく、DB は VNet の中にあって外からコマンドを流せない。そこで
送信のきっかけだけを外から受け取る。

| きっかけ | 中身 |
|---|---|
| GitHub Actions（`.github/workflows/countdown-notify.yml`） | 毎日 15:00 UTC（日本時間 0 時）に `POST /countdown/notify/run/` を呼ぶ。`Authorization: Bearer <COUNTDOWN_NOTIFY_TOKEN>` を照合し（`compare_digest`）、合わなければ・未設定なら 404。応答は `{"sent": 送った通数}` |
| 1 日 1 回の定期点検（`edit/checks.py`） | Actions が動かなかった日の予備。その日の最初のアクセスで送る（時刻は 0 時にならない） |
| 手で送る | `python manage.py send_countdown_mails`（App Service の SSH から） |

どれから何度呼ばれても、同じ日に同じ ID には 1 通しか送らない（`Board.notified_on` に送った日を控える）。
1 件の送信に失敗してもほかの ID は止めず、失敗した ID は控えを進めないので、次に呼ばれたときに送り直す。

設定の手順（合言葉を作って App Service と GitHub のシークレットに入れる）は
[deploy.txt](../../deploy.txt) の「カウントダウンのメール通知」。
